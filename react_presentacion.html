02 — DEFINICIÓN
// typeof React

¿Qué es React exactamente?

Una librería de UI, no un framework completo — creada por Meta en 2013

✦ Definición técnica
Biblioteca JavaScript para construir la capa de vista. Solo se encarga de renderizar UI y manejar interacciones. No incluye router, HTTP ni estado global.
✦ Paradigma declarativo
Describes qué quieres ver, no cómo manipular el DOM. React calcula los cambios mínimos necesarios de forma automática.
Declarativo Basado en componentes Learn once, write anywhere
// Imperativo — manipulas el DOM tú mismo const h = document.createElement('h1'); h.textContent = 'Hola mundo'; document.body.appendChild(h); // Declarativo con React — describes el resultado function App() { return <h1>Hola mundo</h1>; } // React decide cómo y cuándo actualizar el DOM ReactDOM.createRoot(document.getElementById('root')) .render(<App />);

04 — SINTAXIS
// JSX

JSX: JavaScript + Markup Fusionados

Extensión sintáctica — Babel la transforma en React.createElement() antes de ejecutar

✦ No es HTML real
JSX es azúcar sintáctico sobre React.createElement(type, props, ...children). El navegador nunca ve JSX.
✦ Reglas obligatorias
✓ Un solo elemento raíz (o <></>)
✓ className en lugar de class
✓ Tags siempre cerrados: <img />
✓ {expr} para cualquier expresión JS
✓ Eventos en camelCase: onClick
// JSX que escribimos nosotros const el = ( <h1 className="titulo"> Hola, {nombre.toUpperCase()} </h1> ); // Lo que Babel genera (JS real) const el = React.createElement( "h1", { className: "titulo" }, "Hola, ", nombre.toUpperCase() ); // Listas con .map() — key obligatorio function Lista({ items }) { return ( <ul> {items.map(item => ( <li key={item.id}>{item.texto}</li> ))} </ul> ); }
05 — COMUNICACIÓN
// props

Props: Flujo de Datos Unidireccional

Datos que fluyen de padre a hijo — siempre de arriba hacia abajo

Padre
─── props ──▶
Hijo
✦ Props son de solo lectura
Un componente nunca modifica sus propias props. Son un contrato de entrada inmutable. Si necesitas cambiar datos, usa state.
✦ children prop especial
Todo lo que se coloca entre las etiquetas llega como props.children. Permite composición avanzada.
// Padre envía props function App() { const manejarClic = () => alert('click!'); return ( <Boton color="#0ea5e9" onClick={manejarClic} disabled={false} > Enviar formulario </Boton> ); } // Hijo recibe y usa props (destructuring) function Boton({ color, onClick, disabled, children }) { return ( <button style={{ background: color }} onClick={onClick} disabled={disabled} > {children} /* "Enviar formulario" */ </button> ); }
06 — ESTADO
// useState

State: La Memoria del Componente

useState — hook fundamental que persiste datos entre renders y dispara actualizaciones

✦ ¿Por qué no una variable normal?
Las variables locales se resetean en cada render. El state persiste y además le avisa a React que debe re-renderizar cuando cambia.
setState() llamado
▼
React re-renderiza el componente
▼
Virtual DOM compara (diffing)
▼
DOM real actualizado mínimamente
// useState retorna [valorActual, setter] import { useState } from 'react'; function Contador() { // desestructuración del par [estado, actualizador] const [cuenta, setCuenta] = useState(0); return ( <div> <p>Clicks: {cuenta}</p> /* setter con valor nuevo */ <button onClick={() => setCuenta(cuenta + 1)}> +1 </button> /* setter con función updater (más seguro) */ <button onClick={() => setCuenta(prev => prev + 1)}> +1 seguro </button> </div> ); }
07 — MOTOR INTERNO
// virtualDOM

Virtual DOM y Reconciliación

Representación en memoria del árbol de UI — hace el DOM real eficiente

✦ El problema
Cada operación en el DOM real puede disparar reflow + repaint en el navegador. Costoso si ocurre decenas de veces por segundo.
✦ La solución
React mantiene un árbol JS ligero en memoria. El algoritmo de diffing (O(n)) encuentra qué cambió y aplica solo esas actualizaciones al DOM real.
Diffing O(n) Reconciliation React Fiber
✦ Proceso de reconciliación
PASO 01 — TRIGGER
setState() o nueva prop → React programa un re-render
PASO 02 — RENDER
React llama al componente y genera el nuevo Virtual DOM
PASO 03 — DIFFING
Compara nodo a nodo el árbol anterior vs el nuevo
PASO 04 — COMMIT
Aplica al DOM real solo los nodos que cambiaron
08 — HOOKS
// hooks

Hooks: API de Ciclo de Vida Funcional

Introducidos en React 16.8 — eliminaron la necesidad de componentes de clase

useState
Estado local. Retorna [valor, setter]. Cada llamada a setter re-renderiza el componente.
useEffect
Efectos secundarios: fetch, DOM, suscripciones. Dependency array controla cuándo se ejecuta.
useContext
Consume un Context sin prop drilling. Cualquier componente accede al valor del Provider más cercano.
useRef
Referencia mutable (.current) que no dispara renders. Ideal para acceder a nodos DOM o guardar timers.
useReducer
Estado complejo con dispatch(action). Patrón Redux a nivel de componente. Predecible y testeable.
useMemo / useCallback
Memoización. Evitan recalcular valores costosos o recrear funciones en cada render innecesariamente.
import { useState, useEffect } from 'react'; function Usuario({ id }) { const [data, setData] = useState(null); useEffect(() => { fetch(`/api/users/${id}`).then(r => r.json()).then(setData); return () => cleanup(); // se ejecuta al desmontar }, [id]); // se re-ejecuta cuando cambia `id` return data ? <h1>{data.nombre}</h1> : <p>Cargando...</p>; }
